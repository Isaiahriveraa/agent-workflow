# Who reads these maps

Read this before writing a map. Update it when the user shows what they already
know or still find hard, so explanations fade as they learn (expertise reversal;
see `design-principles.md`).

## The reader

- Builds web products and runs an AI-agent workflow; owns product and architecture
  decisions, agents write the code.
- Hates reading long plans. Gets flooded by text. Wants the big picture first, then
  one step at a time, at their own pace.
- Wants to understand **why each part exists and why it comes before the next**,
  not just what gets built.
- Learning while building: a short self-check on a consequential choice is welcome;
  quizzes on routine work are not.

## How to write for them

- Bottom line first. Plain words; idea before term.
- One analogy from everyday life, not from computing.
- Trace one real user action through the system.
- Surface at most 3 decisions; say clearly when there are none.

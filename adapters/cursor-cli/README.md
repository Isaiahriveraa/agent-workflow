# Cursor CLI Adapter

This directory documents the Cursor CLI (`cursor-agent`) integration boundary.

## Managed Surfaces
- Symlinked to the hub: `~/.cursor/AGENTS.md -> ~/.agents/AGENTS.md`
- Global rule bridge: `~/.cursor/rules/hub-contract.mdc` (always-apply; instructs Cursor to read `~/.agents/AGENTS.md` at session start and treat it as the operating contract)
- Per-skill symlinks in `~/.cursor/skills/` -> `~/.agents/skills/<name>` (generated by `sync.sh gen-cursor-skills`)

## Loading Behavior (verified empirically, cursor-agent 2026.10.16)
- Cursor CLI does **not** auto-load `~/.cursor/AGENTS.md` into the system context. The rule bridge is what makes the hub contract load globally.
- Cursor CLI **does** load `AGENTS.md` from the workspace root — a symlink to `~/.agents/AGENTS.md` placed in a project root works directly (verified: contract heading and rule names were quoted accurately).
- Skills are discovered from `~/.cursor/skills/` (user skills); Cursor's built-in skills live separately in `~/.cursor/skills-cursor/`.

## Deliberately Not Managed
- `~/.cursor/cli-config.json` (operator-local permissions, display, model settings)
- `~/.cursor/skills-cursor/` (Cursor's own built-in skills, synced by Cursor itself — see its `.sync-manifest.json`)
- `~/.cursor/hooks.json` (no hook bridge yet)
- `~/.cursor/plugins/`, `~/.cursor/projects/`, `~/.cursor/chats/` (runtime-only)

## Scope
- AGENTS.md entrypoint bridging
- Hub skill bridging

## Capability Profile
- agents entrypoint: `bridged` through a global Cursor rule that loads the shared `AGENTS.md`
- skills: `bridged` as per-skill symlinks
- commands: `unsupported` — no Cursor-native command surface in this repo; hub skills reference `~/.agents/scripts` by path, so scripts are reachable through skill instructions
- hub agents: `unsupported` — hub agent definitions are not mapped to Cursor-native subagents
- hooks: `unsupported` — Cursor CLI supports `hooks.json`, but this repo does not manage a Cursor hook bridge yet
- MCP: `native`
- approvals: `native` (via `cli-config.json` permissions)

## Capability Interpretation
- This profile describes what the hub currently manages for Cursor, not every upstream Cursor capability.

## Canonical Boundary
- Workflow policy lives in `prompts/`, `commands/`, and `AGENTS.md`.
- Files in this adapter document the Cursor integration; they must not become the source of truth for workflow behavior.

## Usage
- `sync.sh gen-cursor-skills` — create/repair per-skill symlinks (run after adding new hub skills)
- `sync.sh migrate` — repair all manifest symlinks, regenerate adapter outputs, verify parity
- `sync.sh verify` — check parity without changing anything
